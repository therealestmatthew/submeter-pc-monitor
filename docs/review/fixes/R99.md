# R99. Scrub hides harmless arguments

**What changed.** `src/submeter/privacy/redact.py`: `_SECRET_NAME` matches only whole words of a flag or name, bounded by the start, `-`, `_`, `.` or the end, so `--compass`, `--bypass-cache`, `--passes`, `--tokenizer` and `--max-tokens` no longer count as secret names. `_looks_opaque` exempts a string that contains `/` (a path, whose folders may be long hashes) or has a UUID shape. Two choices beyond the finding's words, both to keep what scrub hid before: `.` counts as a word boundary, so `-Dspring.datasource.password=...` is still hidden, and `secrets` and `credentials` keep matching in the plural. The module docstring now says what R96 asks for, written after R99 as I53 orders: exe_only is the default, scrub is opt-in and best-effort, and the forms it does not hide (paths and UUIDs among them) are listed.

**Test.** `tests/test_privacy.py::test_scrub_keeps_harmless_words_paths_and_uuids`: scrub keeps `--compass`, `--bypass-cache`, a path holding a 32-character hex folder and a UUID, and still hides the value after `--password`.

**Checker defect, fixed in a second commit.** The start bound and the `/` exemption above stopped scrub hiding secrets it hid before R99: the value after `-storepass`, `-keypass`, `--passphrase`, `-passin`, `--authtoken`, `--dbpassword` and `--accesstoken`, the value of `PGPASSWORD=` and `-Djavax.net.ssl.trustStorePassword=`, and a base64 secret with a `/` inside. Now a secret word counts wherever it ends a word of the flag or name (at `-`, `_`, `.` or the end), with no start bound, and `pass` gains `passphrase`, `passin` and `passout`. `pass` after `com` or `by` does not count, so `--compass` and `--bypass-cache` stay kept; `--passes`, `--tokenizer` and `--max-tokens` stay kept by the end bound. The opaque test exempts only a string that starts with `/`; `./`, `~/` and `C:\` paths already fail `_OPAQUE`, which has no `.`, `~`, `:` or `\`. The docstring now names the forms scrub misses that it hid before: a string starting with `/`, and a secret word with more letters or digits after it (`--password2`, `--passwords`). This rule differs from the finding's wording ("bounded by start, '-', '_' or end"), so the owner may want to confirm it.
