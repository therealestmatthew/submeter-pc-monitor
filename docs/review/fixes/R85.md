# R85: histogram.percentile(q=100) returns the top of the scale for time-weighted buckets

**What changed.** `src/submeter/core/histogram.py` `percentile()`: when `q >= 100`, or when the loop ends without reaching the target, it returns the upper edge of the highest non-empty bin instead of `scale.high`. Float weights can leave the plain running sum short of the compensated `sum()` total, which is how the loop used to fall through to 256 cores. The docs/14 sentences in the finding belong to the docs worker.

**Test.** `tests/test_analysis.py::test_top_percentile_is_the_highest_filled_bin_with_float_weights`: ten values from 0.5 to 5.0 cores, each with weight 0.1 s; q=100 must be the upper edge of the bin holding 5.0 cores.
