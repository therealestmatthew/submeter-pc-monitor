# R108: the layer test resolves relative imports and checks that no program imports another

**What changed.** `tests/test_layers.py` only. `imports_of()` now resolves an `ImportFrom` with `level > 0` against the module's package, and expands `from submeter import x` (and `from ..pkg import x`) to `submeter.x` when `x` is a module or package. `LAYER` gains the layer-3 package `programs`, beside `cli` (decision 22, option a). A new `PROGRAMS` set (`collector`, `server`, `launcher`, each a package under `submeter.programs`) and `test_no_program_imports_another` fail when a module in one program imports another program, or when a package under `programs` is not listed.

**Assumption.** The rulings do not fix the package name; the finding offers `daemon` or `programs.collector/.server/.launcher`, and the docs/14 commit was not available to read. This uses `programs` with the three program names. If the docs/14 commit names another package, rename the `LAYER` key and the `home` folder in the test to match. The AGENTS.md:37 wording goes to the owner (I79); it is not edited here.
