# R38. The fixed 30 s gap rule zeroes all CPU at cadences the settings accept, and `submeter top --seconds 31..60` prints zeros

**What changed.** `src/submeter/collector/sampler.py`: `ingest()` takes the expected interval for the tick (`expected_s`, keyword-only, default 1.0 s so existing `ingest(snapshot)` calls stay valid). A tick is a gap only when the interval clock's elapsed time exceeds 3 x expected + the slack, or when R59's suspend test fires; the fixed `gap_after_s=30.0` is gone. A gap batch keeps its process CPU and I/O deltas and its `cpu_busy_s`: the flag marks coverage only. The module docstring says so. `src/submeter/cli.py` `top` passes `--seconds` as the expected interval. `tests/test_baseline.py` gap test (lines 228-233) is reversed: the gap batch keeps the process's 0.2 CPU-s and the machine's 1.5 busy seconds. No proportional split is built in rollup.py (I1). This ships together with G2's R39 (`ae5fc13`): if that commit is reverted, this one must be reverted with it.

**Test.** `tests/test_collector.py::test_a_gap_is_past_three_expected_intervals_and_keeps_its_cpu`: with a 60 s expected interval a 60.05 s tick is not a gap; with the default 1 s, a 35 s stall is a gap whose process keeps its 3.0 CPU-s delta and whose batch keeps 35 busy seconds.
