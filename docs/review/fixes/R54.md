# R54. One process with a non-UTF-8 argument or name stops every raw write while it lives

**What changed.** `src/submeter/store/raw.py`: a `_storable()` helper encodes text with `backslashreplace`, so a lone surrogate (an undecodable byte psutil hands over) is stored as an escape such as `\udce9`. It wraps every stored text field: the command text, the executable, the workload name in `process` and in `workload_raw`, and the event detail. Per the audit, `write()` now enters `_undone_on_error()` with its transaction: if the transaction fails, `_pending`, `_waited`, `_memory` and `_threads` go back to what they were before the call, so they match the file again. The failed tick is lost whole, as its workload rows are.

**Test.** `tests/test_store.py::test_undecodable_text_and_a_failed_write_do_not_stop_later_writes`: a `RawFile` built with `redaction="scrub"` (named, so the test still covers arguments after R96) stores a process whose cmdline is `("tool", "caf\udce9")` and whose exe is `"t\udcffl"` over three ticks; then a write fails inside its transaction (a memory reading SQLite cannot store raises `OverflowError` after another new process was handled), and the next write still registers that process and stores its CPU.
