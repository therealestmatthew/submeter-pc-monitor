# R58. One process's unexpected read error aborts the whole snapshot, and zombies are dropped although their CPU is readable

**What changed.** `src/submeter/providers/psutil_provider.py`: the optional reads (command line, I/O, working folder) also catch `psutil.Error`, `OSError`, `RuntimeError` and `ValueError` and leave that field None; only `AccessDenied` still marks the process restricted, so who lands in Restricted is unchanged (R42's per-field availability is planned). A `ZombieProcess` from the command line keeps the record with its CPU. The CPU and memory block catches the same bare errors as a refusal, and any other failure of one process gives a restricted record instead of aborting `snapshot()`.

**Test.** `tests/test_collector.py::test_failed_reads_keep_the_process`, which introduces the `fake_process` stand-in for `psutil.Process` that later G1 tests reuse: an OSError from `io_counters` and a ValueError from `cwd`, a `ZombieProcess` from `cmdline`, and a RuntimeError from `cpu_times`.

**Platform.** Linux (Python 3.14.5), with psutil replaced by stand-ins. Nothing here ran on Windows.
