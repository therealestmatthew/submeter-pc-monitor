# R59. On Windows the monotonic clock counts sleep, so suspend detection rests only on the 30 s rule

**What changed.** `src/submeter/core/models.py`: `Snapshot` gains `awake: float | None = None`, a reading of the clock that stops during suspend (None when not read). `Snapshot.monotonic` stays the interval clock and is now defined as the clock that counts suspend (I92). `src/submeter/providers/psutil_provider.py`: `snapshot()` reads both through `_clocks()`: CLOCK_BOOTTIME and CLOCK_MONOTONIC on Linux; `time.monotonic()` (QueryPerformanceCounter from Python 3.13) and QueryUnbiasedInterruptTime through ctypes on Windows, the latter used only for the suspend test because it is accurate to a clock tick; elsewhere `time.monotonic()` and None. `src/submeter/collector/sampler.py`: suspend is the interval clock running ahead of the awake clock by more than the slack; this replaces the wall-minus-monotonic test, and with no awake reading there is no suspend test. `tests/test_baseline.py`: the gap test sets both readings (an hour asleep: interval clock +3600 s, awake clock +1 s). The three tests that patch `sys.platform` to win32 now give `ctypes.windll` a stand-in, since `snapshot()` reads the Windows clock. The windows-priorities and docs/17 text is the docs worker's.

**Test.** `tests/test_collector.py::test_suspend_is_told_by_the_clock_that_stops_not_by_the_wall_clock`: a tick where the interval clock gains 3 s more than the awake clock while the wall clock is stepped back an hour is a gap; the next tick, where both clocks agree and the wall clock jumps 100 s ahead, is not. The suspend is 3 s rather than the plan's 60 s so that neither today's 30 s rule nor R38's stall rule (3 x expected + slack) can mark the tick; only the suspend test does.
