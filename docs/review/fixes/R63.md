# R63. On Linux the baseline stores psutil's name() as exe, which differs from the executable's file name for about one in six readable processes

**What changed.** `src/submeter/providers/psutil_provider.py`: `exe` is the base name of psutil `exe()`, falling back to `name()` when `exe()` fails or is empty; `name()` is stored separately. `src/submeter/core/models.py`: `ProcessCounters` and `ProcessSample` gain `name: str = ""`, and `src/submeter/collector/sampler.py` copies it. `src/submeter/attribution/rules.py` (the Rule fields after exe, `_usable` and `matches` only; line 62 left to G4): a `name` condition, and `exe` and `name` both match as case-insensitive glob patterns. The docs/08 and examples/rules.toml text is the docs worker's (I46, I70).

**Test.** `tests/test_collector.py::test_exe_is_the_executable_file_and_name_is_kept_apart`: a stand-in with `exe()` `/usr/bin/python3.12` and `name()` `pytest`, through the real provider and sampler, gives exe `python3.12` and name `pytest`, and `Rule(workload="x", exe=("python3*",))` and `Rule(workload="y", name=("pytest",))` each match it. The `fake_process` stand-in gains an `exe()` read.
