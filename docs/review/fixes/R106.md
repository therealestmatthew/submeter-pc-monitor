# R106: Workload names are validated

**What changed.** New `src/submeter/core/names.py` (layer 0) defines `WorkloadName`, which must match `[a-z0-9][a-z0-9._:-]{0,63}` and refuses the reserved names system, restricted, unattributed, submeter and machine, and `WorkloadPattern`, the same characters plus `*`, with no reserved names refused, so an alert rule can name `machine` and `submeter`. `Rule.workload` in `src/submeter/attribution/rules.py` and `AlertRule.workload` in `src/submeter/core/config.py` use them. `submeter run --as` does not exist yet; it adopts `WorkloadName` when it is built.

**Test.** `tests/test_settings.py::test_workload_names_are_checked`: `Rule(workload=...)` with "system", "<b>x</b>" or "../x" is refused on the workload field, and `AlertRule` with workload "build*" or "machine" is accepted.
