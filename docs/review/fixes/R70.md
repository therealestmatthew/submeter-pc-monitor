# R70. The psutil fallback is not independent of the bulk snapshot (thread counts on Windows)

**What changed.** `src/submeter/core/models.py`: `ProcessCounters.threads` and `ProcessSample.threads` become `int | None`; the counters' default is None, so a record the provider could not read no longer reports zero threads. `src/submeter/providers/psutil_provider.py`: on Windows `num_threads()` is not called (psutil answers it with a whole-system query per process) and threads is None; the unreadable stand-in also writes None. `src/submeter/store/raw.py`: the `process_raw.threads` column is nullable (line 48) and the annotations at lines 83 and 172 widen to `int | None`; `_row`'s signature is reflowed by the formatter. SCHEMA_VERSION stays 1 (I9). The docs/17 and docs/16 sentences are the docs worker's.

**Test.** `tests/test_collector.py::test_windows_threads_are_unavailable`: with `sys.platform` patched to win32, the stand-in's `num_threads` is never called, the sample's threads is None, and a `RawFile` stores NULL threads for it.
