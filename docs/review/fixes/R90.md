# R90. A quiet process's CPU is held in memory until a keyframe

**What changed.** `src/submeter/store/raw.py`: a process row is also written when CPU is pending and the time waited reaches `HELD_CPU_LIMIT_S` (60 s). `RawFile` remembers the last committed batch's `taken_at`; when a batch falls in a new UTC hour, `write()` first writes each process's pending CPU stamped with that previous `taken_at` (`_flush`), then handles the new batch, in the same transaction (I40). A process with nothing pending gets no extra row, so idle processes with zero CPU are not written every minute. `RawStore` already closes a day's file with its last `taken_at` (raw.py:266-267), so day rollover needs no change.

**Test.** `tests/test_store.py::test_a_quiet_process_gets_a_row_each_minute_and_none_crosses_an_hour`: one process at 0.1% of a core with 1 s ticks from 99 s before an hour to 100 s after it. Its rows are at -99 s (first seen), -39 s (60 s held), -1 s (the last tick before the hour, holding only the previous hour's CPU) and +59 s (60 s held, only new-hour CPU).
