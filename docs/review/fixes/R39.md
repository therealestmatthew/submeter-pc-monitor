# R39. A gap is stored and rolled up as covered zero-use time

**What changed.** `src/submeter/core/models.py`: `WorkloadSample.gap: bool = False`, and `Bucket.memory_mean` is `float | None`. `src/submeter/attribution/rules.py`: `aggregate()` passes `gap=batch.gap`. `src/submeter/store/raw.py`: `workload_raw` and `system_raw` gain a `gap` column, and `workload_samples()` returns it; `SCHEMA_VERSION` stays 1 (I9). `src/submeter/store/rollup.py`: a gap sample adds CPU, I/O, started, the process maximum and its memory reading (minimum, maximum, last) to the bucket, and nothing to `covered_s`, `samples`, `active_s`, the memory weight or either histogram. `close()` returns a bucket holding only gap samples, with `memory_mean` None; `merge()` weights `memory_mean` over covered buckets only. The reject clause for long non-gap samples is left out (I1), and the awake seconds of I2 wait for the planned store task.
