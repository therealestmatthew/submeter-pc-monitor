## Goal

A refused CPU read is `None`, never a stand-in record with `started=0.0`; a process whose start time cannot be read is only counted; each credited CPU delta is capped at `interval_s × logical cores` and the capped samples are counted. A process's start stamp is the platform's integer (clock ticks since boot with `boot_id` on Linux, the FILETIME integer on Windows), so a wall-clock step no longer cuts a child from its parent on Linux and a re-read never re-keys a process. The optional per-process fields reach `ProcessSample`.

## Uses

2. **Then R56** (`docs/review/02-rulings.md:284`):
   - Linux: the start stamp is field 22 of `/proc/PID/stat` (clock ticks since boot), read by the provider's own Linux branch (I12), with `boot_id` on the Snapshot and in the raw file's `meta` table. Parse field 22 after the last `)`, because the command name in field 2 may hold spaces and parentheses.
   - Windows: CreateTime as the FILETIME integer `GetProcessTimes` returns, read on a handle opened with `PROCESS_QUERY_LIMITED_INFORMATION`, never psutil's `create_time()`: that float's spacing near 1.8e9 s is 2.4e-7 s, wider than the FILETIME's 100 ns unit (of 100,000 random FILETIMEs of November 2026, 57,809 changed when converted to that float and back; `docs/PLAN.md` 3.4).
   - The stamp is read once for each new pid and kept while psutil's float for that pid is unchanged. A refused open puts the process in the unreadable count (I42 (b)).
   - The born-in-interval test (`sampler.py:87`) and the parent comparison (`rules.py:165`) use the boot clock. On Windows see CQ-11.
   - `process.started` and `process_raw.started` become `INTEGER` (`raw.py:41,50`); the raw `SCHEMA_VERSION` stays 1 (I9). The pid file records the same stamp (`files.py:254-256,274`; I43).
   - `platform_check.py` skips `None` CPU in its reconciliation check (`docs/review/fixes/R41.md`).
3. **The sampler** copies each optional per-process field P0-W3-T1 added to `ProcessCounters` into the `ProcessSample` it builds (`sampler.py:91-105`); `None` stays `None`.
4. **`tests/test_platform_check.py`** loads `scripts/platform_check.py` by path with importlib and runs its provider, reconciliation and SQLite checks in `tmp_path`, so that a later change to an interface the script calls fails on every push; `uv run mypy src tests` does not check `scripts/`.

## Rules that bear on this task

- `AGENTS.md`: a process is identified by pid plus start time (`ProcessKey`), never by pid alone; a process without a readable start time has no key and is only counted (I42 (b)).
- `AGENTS.md`: providers return cumulative counters; only the sampler turns them into deltas, and only the sampler caps them.
- `AGENTS.md`: a metric the system cannot deliver is unavailable, never zero: a refused CPU read is `None`. Crediting 0 for an interval with no baseline is the sampler's delta rule (R57), not a stored 0 reading.
- `AGENTS.md`: each data file has one writer; the raw schema change keeps `SCHEMA_VERSION` 1 (I9).
- Fixed rule 1 (observe only) and rule 2 (no administrator rights): the Windows read opens processes with `PROCESS_QUERY_LIMITED_INFORMATION` only, which a standard user may use; a refused open is counted, never retried with more rights.
- C5: `boot_id` on the `Snapshot` and in the raw file's `meta` table.

## Questions for the lead

- `CQ-11`: On Windows the stamp is CreateTime, the system time at which the process was created, so it is a wall-clock value. A backward wall-clock step between a parent's and a child's creation makes the child's stamp earlier than its parent's, and the parent comparison at `rules.py:165` would then cut the child, which is R56's finding. The rulings give "FILETIME on Windows" without saying how the comparison is made safe there. Default: `test_a_wall_clock_step_does_not_cut_a_child_from_its_parent` runs on Linux, where the stamp counts from boot; on Windows it is skipped with the reason "Linux only: on Windows CreateTime is wall-clock time (CQ-11)", which names the other system as gate criterion S2 requires, and the lead puts the Windows case to the owner as a known limit or a follow-up task. If the answer is that Windows must pass too, the card needs a Windows boot-relative stamp, which no ruling gives. The owner answers the Windows case (a known limit or a follow-up task); the lead answers the rest (`docs/STATUS.md` 7.3).
