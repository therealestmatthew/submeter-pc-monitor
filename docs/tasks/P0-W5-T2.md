## Goal

A probe the owner runs once shows whether a standard user can register, read back, run and delete a logon task with the settings `docs/17-build-prompt.md:260` gives, and whether policy lets a program in a user-writable folder run at all. Its result decides B3: the scheduled task, or the `HKCU\...\Run` key.

## Uses

`schtasks /Create /XML`, `/Query /XML`, `/Run`, `/Delete`; `Get-AppLockerPolicy -Effective -Xml` and the Device Guard status, through `powershell.exe -NoProfile -Command`.

## Provides

`scripts/probes/autostart.py`, run as `uv run python scripts/probes/autostart.py`, prints: the exit code of each `schtasks` call; the read-back XML; the comparison of the 8 settings, one line each; whether `/Run` wrote its marker file; the effective AppLocker policy and the Device Guard status; and the decision row for B3 ("scheduled task" if `/Create` exits 0 as the standard user, otherwise "HKCU Run key"). The owner saves it as `docs/review/ground-windows/probes/autostart.txt` in P0-O2, with names replaced. `scripts/probes/autostart_task.xml` is the task definition it registers. P0.10 reads it; B3 decides P3-W5-T3.

## Work

1. `autostart_task.xml` carries the 8 settings of `docs/17-build-prompt.md:260`: an `InteractiveToken` logon trigger for the current user, `DisallowStartIfOnBatteries` false, `StopIfGoingOnBatteries` false, `ExecutionTimeLimit` `PT0S`, `MultipleInstancesPolicy` `IgnoreNew`, restart on failure, `Priority` 5, `RunLevel` `LeastPrivilege`. The probe fills in the current user when it registers.
2. The probe registers the task, reads it back, compares each of the 8 settings, runs it once with an action that writes a marker file, checks the marker, and deletes the task. It then records the effective AppLocker policy and the Device Guard status.
3. Builder's choice, named in the report: the task's name (it must not be the name `daemon install` will use, and it includes "probe"), and the marker file's folder (under the user's temporary folder). The probe deletes the task even when an earlier step failed, and says if the delete failed.
4. The XML generation and the comparison are functions the tests call; the `schtasks` and PowerShell calls happen only in `main()`, which says it needs Windows on other systems and exits non-zero.

## Rules that bear on this task

- Fixed rule 2 (no administrator rights): the task registers with `RunLevel` `LeastPrivilege` for the current user only; a refused registration is a result (the Run key decision), never retried with more rights.
- Fixed rule 1 (observe only): the probe changes no other process. `Priority` 5 is the start priority of the task's own action, set in its own definition (`docs/17-build-prompt.md:260`); it does not change a running process.
- Fixed rule 3 (nothing leaves the machine): no network use; the output's user and host names are replaced before commit (P0-O2).
- The probe leaves nothing behind: the task is deleted and the marker file removed.
