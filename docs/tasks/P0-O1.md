## Work

On the personal Windows 11 PC:

1. In a PowerShell started normally (not "Run as administrator"), in a clone at the P0-W1 integration commit, follow `docs/review/ground-windows/step1-procedure.md` from its first step to its last.
2. Read every file before the commit. Nothing recorded on the personal PC is pushed unread (prompt 6.5).
3. Run `uv run python scripts/probes/replace_names.py docs/review/ground-windows/step1`, then the `git grep` name check of `docs/PLAN.md` 6.2 step 4, which must print nothing; change any line it prints to `<user>` or `<host>` and repeat.
4. Commit only that folder on `owner/P0-O1` and push it. The lead has a code reviewer read the branch and merges it with the check that it touches only that folder (`docs/PLAN.md` 6.2 step 5).
5. If a standard user cannot read the Defender log, the error is the content of `defender-asr.txt` and the owner rules how it is read (Q4). Any event 1121 or 1122 naming python.exe stops the build for a ruling (`docs/PLAN.md` 6.4, P0.3; prompt section 1, stop rule 5).

Then on the work PC (`docs/PLAN.md` 6.2 step 4):

6. In a PowerShell started normally, in a clone at the commit the lead names (Base commit above), follow the procedure up to and including its summary screen. Make no branch, no commit and no push, and copy no file, figure or text off the machine.
7. Tell the lead the word for each item of the summary screen (the table under Provides). The lead records them as the owner's statement with the date in `docs/STATUS.md` section 5, table "Work PC results by word".
8. Remove the temporary folders the run made, as the procedure's last step says.
9. A request to elevate, or a block by security software or policy (an attack surface reduction event, an AppLocker or Device Guard refusal, a quarantined file), stops the build: tell the lead and never work round it (prompt section 1, stop rules 4 and 5).
